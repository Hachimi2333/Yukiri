# 渲染

运行基线为 Vulkan 1.4，使用 volk、VMA、Dynamic Rendering 和 Synchronization2。GLSL 在构建时编译为嵌入式 SPIR-V；运行时不需要着色器编译器或 SDK。

应用共享 Vulkan 设备与 VMA allocator。每个窗口独立拥有交换链、管线和两个帧槽；每槽保存命令缓冲、顶点缓冲、acquire semaphore 和 fence。present semaphore 按交换链图像分配，避免错误复用。

选择支持呈现的 Vulkan 1.4 图形队列，启用 dynamicRendering 和 synchronization2。使用 sRGB 交换链、线性空间颜色和预乘 Alpha。矩形 / 圆角使用解析距离场抗锯齿，文字使用 R8 图集。绘制列表按原始顺序合并相邻纹理 / 裁剪批次，保留透明叠放顺序。Canvas 提供矩形、边框、圆角、线条、文字、平移与裁剪栈。

标题栏图标使用内部 RGBA sRGB 纹理路径；采样时转换到线性空间，着色器输出预乘 Alpha，与文字和几何图形一致。R8 / RGBA 上传各自按像素字节数计算脏区行跨度和暂存偏移。图标按宿主资源标识和 DPI 尺寸缓存到应用共享设备，设备销毁时释放；不新增公开图片或 SVG API。

字形使用实际像素字号栅格化，四边形落点对齐像素网格，减少分数 DPI 下重复采样带来的模糊。图集首次上传完整页，后续只上传脏矩形。上传记录在正常帧命令中，映射暂存缓冲随帧 fence 回收和复用，不再为字形更新等待整个队列空闲。普通帧使用映射顶点缓冲。

交换链尺寸变化、out-of-date 和 suboptimal 在安全等待后重建，并保留重绘请求。最小化或零尺寸不提交。窗口资源先于共享设备释放；设备销毁前等待 GPU 完成。

`YUKIRI_TRACE_FRAMES=1` 在窗口渲染器销毁时打印提交帧数。配合 Demo 的 `--idle-smoke` 可检查空闲窗口不连续重绘。实际 GPU、验证层与帧数结果见 [验证记录](Validation.md)。

## 刷新率与调度

FIFO 垂直同步始终开启。每个窗口通过 SDL 所在显示器的精确刷新率维护单调时钟 deadline；跨屏和显示模式事件重新读取。更新、命令记录和呈现阻塞已经占用的时间不再重复等待，迟帧跳过过期时点。未知刷新率使用 FIFO 背压与有界资源重试。

GPU fence 和交换链 acquire 使用非阻塞检查；未就绪时保留最新失效状态并延后重试，先服务其他窗口。Poll(false) 不睡眠，未必完成一次呈现；外部循环必须持续驱动。空闲窗口等待事件，活动帧只在最后的亚毫秒尾段使用精确等待。

设置 YUKIRI_FRAME_STATS=1，在窗口销毁时输出刷新率、首帧 CPU、预热 CPU / 呈现调用 / 提交间隔的分位数，以及资源延后时间与重试次数。前十帧作为预热，采样内存有界。提交和绘制间隔不是物理显示帧率。

测试目标 YukiriFrameBenchmark [seconds] 以 SDL 内部事件持续交替悬停两个按钮；追加 --scroll 可持续反向滚动文本列表，并记录预热后的内容测量次数。追加 --settle 可检查停止输入后是否停止绘制。不移动系统鼠标。适合对比同一机器的帧节奏，不加入无 GPU 的 CTest。
